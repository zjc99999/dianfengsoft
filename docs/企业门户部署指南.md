## 2. 首次部署（Cloudflare Pages，Git 集成 = 方案 A 零密钥）

### 2.1 准备仓库

```bash
# 本地已 git init 并完成首次提交（commit 2f0817d，167 文件，.gitignore 排除 .env）
git remote add origin https://github.com/<你的账号>/<仓库名>.git   # 待提供仓库地址
git push -u origin HEAD
```

> 旧站仓库为 `zjc99999/website`（另一项目）。企业门户建议新建独立仓库或复用同一 CF 账号下的新 Pages 项目，
> 避免覆盖旧站部署。凭据用 HTTPS PAT 或 SSH key，不入库、不发明文。

### 2.2 CF Pages 构建配置（Settings → Builds & deployments → Build configuration）

- **Build command** = `pnpm build`
- **Build output directory** = `dist`
- **Environment variables**：
  - `PNPM_VERSION` = `11.28.5`（CF Build image v3 默认 pnpm 10.x，不识别 `packageManager` 字段，必须显式设）
  - `PUBLIC_SITE_URL` = `https://www.dianfengsoft.cn`（代码已内置该默认值，可省略；显式设更稳妥）
  - `PUBLIC_CONTACT_EMAIL` = `zjc_9999@163.com`（已内置默认值）
  - `PUBLIC_FORM_ENDPOINT` = 第三方表单端点（如 Formspree / 自建 serverless；**留空则表单降级 mailto**，商务闭环的外部送达环节暂不生效）
  - `PUBLIC_UMAMI_SCRIPT_URL` + `PUBLIC_UMAMI_WEBSITE_ID`：可选，必须同时设；否则首屏零客户端 JS

⚠️ **CSP 顺序硬约束**：`PUBLIC_FORM_ENDPOINT` / `PUBLIC_UMAMI_*` 必须在**首次构建之前**设好。
CSP 从产物 HTML 里真实出现的外链推导 `form-action` / `script-src`；先构建后补变量会导致外链被静默拦截。
改动 `/search` 内联脚本须重跑 `pnpm test:csp` 更新 `public/_headers` 哈希。

### 2.3 自定义域名与 DNS

1. 先在 Pages 后台 **Custom domains → Set up a domain** 填 `www.dianfengsoft.cn`，
   让 CF 自动建 CNAME（**子域名用 CNAME，不用 A 记录**；先手动加 CNAME 会解析到 522）。
2. 若 `dianfengsoft.cn` 的 NS 未托管在 CF，需在域名注册商处把 NS 指向 CF，或按 CF 给出的 CNAME 目标手动配置。
3. 等 HTTPS 证书签发。**备案**：`苏ICP备2026086890号-2` 已在页脚展示；按用户确认，-2 与子域名无关、备案无问题。
4. 焕名子域 `ren.dianfengsoft.cn` 保持不变，门户与焕名互链（CTA「免费试用焕名」已指向 `https://ren.dianfengsoft.cn`）。

### 2.4 部署后冒烟（关键：CI 绿 ≠ 线上产物正确）

```bash
pnpm deploy:smoke:remote https://www.dianfengsoft.cn   # 自定义域名生效后
pnpm deploy:smoke:remote https://<项目域>.pages.dev     # 平台默认域先验
```

验收点：16 核心页 200、单一 h1、canonical 为真实域名、RSS/JSON Feed/sitemap/Pagefind 可消费、
CSP 作为真响应头发出、首屏零脚本、图片带 srcset、无 `website.85138175.xyz` / `atelier` 残留。

> 历史教训（旧站踩过）：CF 曾报 "Deploy successful" 却发布源码目录而非 dist/，直到 `deploy:smoke:remote` 才发现。
> 根因是没配 Build command / 输出目录。本指南 §2.2 的配置就是为避免重蹈覆辙。

## 3. 回滚

纯静态站，回滚 = 重新指向上一份成功部署的产物，无需回滚数据库。
在 **Workers & Pages → 项目 → Deployments → All deployments** 按**部署 ID 精确选中**基线那份 →
Rollback to this deployment → 完成后跑 `pnpm deploy:smoke:remote` 确认内容回到基线。
（详见 `部署与回滚演练.md` §4 的实证流程；注意文档回填提交也会触发部署，「选上一份」可能点错。）
