## 1. 执行摘要（结论先行）

**一句话结论**：这不是「重新开发一套网站」，而是**把已跑通的 Atelier 工程骨架，升级为以企业为主体的门户**——保留其「简洁明了 + 证据链 + 静态优先 + 质量门禁」的基因，替换品牌与信息架构，补齐企业门户必需的「使命初衷、解决方案、客户案例、专业能力、社会责任、商务线索、合规信息」。技术复用率预计 **80%+**，真正需要新做的是**企业叙事与内容结构**，不是底层系统。

**五个核心判断**：

1. **主体变了，叙事中心必须跟着变**。个人站的中心是「我是谁」；企业门户的中心是「**我们为什么存在（初衷/使命）→ 我们能解决什么（解决方案）→ 我们凭什么可信（作品/案例/能力）→ 我们对社会承诺什么（社会责任）**」。
2. **不要推倒重来**。旧项目有完整的 Astro 7 + Content Layer + Zod 校验、质量门禁（Lighthouse 100/100/100/100、axe 0）、CI 四段、Cloudflare Pages 发布/回滚演练——这是稀缺资产。企业门户应**继承工程、重构内容**。
3. **焕名是现成的「企业能力样本」**。`ren.dianfengsoft.cn` 已有企业版、商户支付、ICP 备案、隐私/退款/协议等完整商业要素，应成为门户「产品与案例」的旗舰证据，门户则是它的**品牌母体与信任背书**。
4. **「简洁明了」要升级为「企业级的克制」**：首屏一句话讲清定位、导航克制、信息分层（3 秒 / 30 秒 / 3 分钟）、不用轮播和弹窗、用真实数据与授权案例建立信任。
5. **最大风险是「空壳化」与「合规缺位」**。因此本版把「内容真实性原则」和「合规前置清单」写进正文（第 12 节），并明确**不靠配图填充、不写伪案例**——这是本次讨论收敛出的关键结论。

**推荐路线**：`P0 决策与素材 → P1 门户骨架上线（全栏目，3~4 周） → P2 商务闭环深化 → P3 运营演进`。

## 3. 需求解读与定位

### 3.1 从「个人主页」到「企业门户」的位移

| 维度 | 旧站（个人） | 新门户（企业） |
| --- | --- | --- |
| 中心问题 | 我是谁、我做过什么、怎么联系我 | **我们为何存在、能为你解决什么、凭什么信我们、如何合作** |
| 信任来源 | 创作过程公开、能力挂证据 | 初衷 + 使命、真实产品/场景、专业能力、合规信息 |
| 内容节奏 | 高频碎片日志 | 中频洞察 + 低频精品场景/方案 |
| 转化目标 | 订阅 + 预约 + 线索池 | **商务咨询 + 企业版合作 + 渠道合作** |
| 受众 | 同行、潜在客户 | 企业客户、渠道伙伴、求职者、公众、媒体 |
| 合规要求 | 隐私政策 + 显式同意 | 同上 + **ICP 备案展示、企业信息、用户/退款协议** |

### 3.2 目标受众与场景（JTBD）

| 角色 | 他来干什么 | 设计响应 |
| --- | --- | --- |
| 企业客户 / 采购 | 「能解决我的什么问题？靠谱吗？怎么谈？」 | 解决方案按场景组织 + 场景证据 + 商务咨询入口 |
| 个人用户 | 「焕名是什么？怎么买？安全吗？」 | 产品卡片直链焕名站 + 免费试用 + 隐私承诺 |
| 渠道 / 合作伙伴 | 「能不能代理、定制、私有化？」 | 合作方式入口 + 企业版咨询 |
| 求职者 / 公众 | 「这是一家什么样的公司？」 | 关于我们（初衷/使命/团队）+ 社会责任 |
| 搜索引擎 / 媒体 | 「可引用的权威信息在哪？」 | 结构化数据、清晰企业名称与业务描述 |

### 3.3 核心叙事主线

```
成立初衷（为什么做）  →  专业能力（凭什么做）  →  作品/产品（做出来了什么）
      ↓                                                    ↓
  社会责任（对社会的承诺）  ←  典型应用场景（用起来怎样）  ←  解决方案（怎么帮你做）
```

- **初衷/使命**：信息技术与 AI 应用服务于大众——强调「普惠、实用、可信」。
- **解决方案**：把能力翻译成客户听得懂的「场景 → 做法 → 结果」，与「产品列表」区分。
- **专业能力**：继承证据链，每条能力挂到作品/场景/洞察。
- **社会责任**：每条承诺绑定可验证事实（本地优先不上传、免费层普惠、隐私默认），避免空喊口号。

## 4. 市场与对标分析

### 4.1 通用范式

主流企业官网栏目高度趋同：**首页（价值主张 + CTA + 信任信号）｜产品/解决方案｜客户案例｜关于我们｜新闻洞察｜联系我们**，并配齐隐私、条款、备案等法务信息。差异主要在**叙事起点**：产品公司从产品讲起，AI 公司从使命/研究讲起。

## 6. 信息架构（IA）与页面规格

### 6.1 站点地图（全部栏目进 P1）

```
/                          首页（3 秒层：使命定位 + 核心业务 + 代表作品 + 动态入口）
├── /solutions             解决方案（按场景：个人效率 / 企业文件治理 / AI 应用集成…）  [P1]
│   └── /solutions/[slug]  方案详情（场景→做法→结果→相关产品/场景）
├── /products              产品与作品（列表）
│   └── /products/[slug]   产品详情（痛点→功能→证据→价格/试用→FAQ）
├── /cases                 客户案例 / 典型应用场景（场景演示无需授权；真实案例需 consent） [P1]
│   └── /cases/[slug]
├── /capabilities          专业能力（能力 + 证据链）
├── /about                 关于我们（成立初衷 / 使命 / 团队 / 历程 / 资质）
├── /responsibility        社会责任（隐私默认 / 普惠免费层 / 本地优先 / 开源公益）  [P1]
├── /insights              洞察与实践（自有内容：焕名更新 / 开发手记 / AI 实践）  [P1]
│   └── /insights/[slug]
├── /contact               联系与合作（独立轻量商务咨询入口）
├── /privacy /terms /refund 法务页（对齐焕名口径）
└── /search                站内搜索（Pagefind，构建期索引）
```

## 12. 对本次讨论疑问的回应（内容真实性与合规前置）

### 12.1 关于「没内容的栏目配相关图文填充」

**我的意见：不建议。** 为了「不空」而配装饰图/通用图文，正是空壳化的典型症状，反而显得假、削弱可信度。原则是：

> **宁可真实地少，不可虚假地满。**

既然栏目全进 P1，就给每个栏目至少 **1 条真实内容**打底，导航照常展示全部栏目，但点进去必须有真东西。可行的真实打底方案：

| 栏目 | 真实打底内容 |
| --- | --- |
| 解决方案 | 从焕名真实能力写 1~2 个场景：本地文件治理、隐私优先的 AI 命名 |
| 场景案例 | 「典型应用场景」：焕名真实截图 + 工作流演示（见 12.2） |
| 社会责任 | 真实事实：本地页 0 上传、免费层永久免费、隐私政策公开 |
| 洞察与实践 | 旧站 14 篇日志挑 3 篇重写 + 焕名版本更新 |
| 专业能力 | 迁移旧站 2 篇能力（挂真实证据链） |

### 12.2 关于「典型应用图文冠名某单位」

**我的意见：明确不建议虚构客户。** 既然目前没有可公开的客户案例，给产品图冠以「某单位」并作为案例展示，本质是**虚构案例**——既是法律风险（虚假宣传 / 误导），也会在懂行的人面前崩塌信任，与「合规前置」直接冲突。

建议做法：

- `/cases` 上线初期只放**「典型应用场景」**：用焕名真实截图和工作流，明确标注为**场景演示 / 产品工作流**，不指向任何具体客户；
- 等拿到书面授权，再发真正的**客户案例**（`/cases/[slug]`，`kind = client`，走 `consent` 硬校验）；
- 若确有真实客户同意匿名，可写「某单位（应客户要求匿名）」，但须留存授权证据备查。

这样既让栏目不空、视觉丰富，又 100% 诚实、合规。

### 12.3 关于「AI动态」板块

**我的意见：不单设，你的「不伦不类」直觉是对的。** 通用 AI 新闻聚合对小软件公司既难持续、又无差异化，还容易变成搬运，反而加速空壳化。

替代方案：把已有的 `/insights` 做成**「洞察与实践」**——内容全部是**我们自己的**：

- 焕名版本更新与功能背后故事；
- 开发手记与技术决策（怎么做的、为什么这么做）；
- 「AI 按内容命名」这类功能**如何兼顾隐私**的实践。

AI 相关话题统一以「我们的 AI 实践」角度写在 `/insights`，而不是做行业新闻搬运。这既解决反空壳（内容源来自真实工作、可持续），又对标 DeepSeek 研究 / Anthropic Research 的「用自己的实践建立权威」，还名正言顺、不突兀。**因此不新增独立栏目，强化既有 `/insights` 即可。**
