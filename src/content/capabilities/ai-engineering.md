## 主张：Demo 里能调通，和线上能交付，是两回事

调用一个大模型 API 不难，难的是把它变成生产系统：模型随时可能挂、返回可能不合契约、成本要算得清、用户输入的数据要合规处理。AI 应用工程化的能力，就是把这些「Demo 里不存在的问题」在生产环境里一一解决。

## 多模型适配，不被单一供应商绑死

照水的 `core/llm.js` 是一个 14 模型适配层（DeepSeek / GLM / Qwen / 豆包 / Kimi / OpenAI / Anthropic / 本地 llama.cpp 等），OpenAI 兼容与 Anthropic 原生双分支；带 JSON 契约校验（失败重试并把错误原话回传模型）、主备链自动切换、全挂降级到本地签文池。这意味着一个模型服务出问题，产品不会跟着停摆。焕名的 AI 整理页则把 API 交由用户自配，把模型选择权与数据边界一并交给用户。

## 让质量与成本都可度量

AI 输出不能只看「感觉不错」：照水设了语气守门员（11 类禁用句式，实时标记、离线重写），做语气 A/B 实测（禁用句式从 3/14 降到 0/14）；计费上把单次开示压到约 ¥0.005、一万次不到 50 元，把单位经济算到了每一分。感知延迟也是可优化的工程指标——用首屏预取把 9.2 秒降到 3.1 秒。

## 合规做进链路，而不是贴声明

数据出境是 AI 应用的硬约束：照水坚持用户输入由境内模型处理；内容合规上做关键词前置拦截 + 危机热线一键拨打，敏感内容不渲染卡片；付费明确「不自动扣款」。这些不是文案，而是写进代码路径的产品能力。**AI 工程化的终点，是把模型能力变成可信、可控、可运营的产品服务**。
